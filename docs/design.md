# FreeStatus 核心设计

模板定义字段名，插件实现字段类型。声明（模板）与数据（状态）分离，渲染、提示词、回注都从模板派生。

## 1. 总览与数据流

```
AI 回复尾部 ```fs {"_char":"玲","affection":45,...}``` （有值快照，只含有值键）
        │
        ▼
MESSAGE_RECEIVED ──► 解析容错（截断丢弃 / 静默回退）──► 合并写入 chatMetadata
        │                                                    │
        ▼                                                    ├─► 侧栏卡片渲染（客户端）
CHARACTER_MESSAGE_RENDERED ──► 隐藏原始 ```fs 块             │
                                                               └─► 可选回注（interceptor / 宏）
生成下一条前 ──► generate_interceptor / {{fs_state}} ──► 提示词中附当前状态
```

四条原则：

1. 单一数据源。AI 输出、侧栏显示、回注提示词读同一份状态对象，两侧数值始终一致。
2. 声明驱动。模板决定 AI 被要求输出哪些键、侧栏渲染顺序与样式、提示词字段清单，改模板等于改协议。
3. 宽容解析。解析器只求拿得到 JSON 对象，拿到什么渲什么，状态块残缺时对话照常继续。
4. 轻量。无独立 LLM 请求、无构建步骤、无框架依赖；关闭回注后每轮只花状态块本身的 token。

## 2. 模板系统

### 2.1 模板结构

```json
{
  "id": "default",
  "name": "通用状态模板",
  "version": 1,
  "fields": [
    {
      "key": "affection",        // AI 输出的键名（协议中的 JSON key）
      "label": "好感",           // 侧栏显示名
      "kind": "bar",             // 字段类型，见 2.2
      "max": 100,                // 仅 bar/tag 数值有意义，默认 100
      "min": 0,                  // 默认 0
      "color": "#e8577a",        // 进度条/徽章着色，缺省取主题色
      "default": 0,              // 该字段初始值（chip/text 为字符串默认值）
      "inject": true,            // 是否参与回注（不回注的字段不进提示词）
      "locked": false            // 默认锁定状态，锁定后忽略 AI 更新
    }
  ]
}
```

- `key` 在模板内唯一；AI 输出的 JSON key 与它一致，提示词由模板生成，两边始终对齐。
- 模板存在 `extensionSettings.freestatus.templates[]`（全局），每聊可指定当前生效的模板 id（`chatMetadata.freestatus.templateId`），一个聊天一套字段。
- 未知键策略：AI 输出了模板没有的键（如临时剧情项），按值类型推断渲染（数字→bar、真/假→check、数组→list、对象→tag、字符串→chip），显示在卡片「其他」分组，并提供「收编进模板」（一键按推断类型加入 fields）与「忽略此后不再显示」。

### 2.2 六种字段类型（kind）

| kind | 值形态 | 渲染 | 典型用途 |
|---|---|---|---|
| `bar` | number 0..max | 进度条 + 数值，可拖动/输入 | 各项 0–100 数值 |
| `chip` | string（短语） | 彩色圆角小标签 | 心情一类的短语 |
| `text` | string（长文） | 可换行文本段 | 状态描述 |
| `tag` | object `{键: number\|string}` | 键值行，数值带迷你条 | 对象到程度/数量的映射 |
| `list` | string[] | 标签组 | 随身条目、穿着 |
| `check` | boolean | 徽章（是/否、有/无） | 开关标记 |

类型决定渲染、校验和钳制：`bar` 收到非数字按 0 处理并钳到 [min,max]；`check` 只认严格 true/false；`list` 自动去重限长（≤20 条）。

### 2.3 内置通用模板（默认模板）

| key | label | kind | 说明 |
|---|---|---|---|
| `affection` | 好感 | bar | 0–100 |
| `trust` | 信任 | bar | 0–100 |
| `mood` | 心情 | chip | 短语 |
| `condition` | 状态 | text | 一句话 |
| `impressions` | 印象 | tag | 键=对象，值=0–100 程度 |
| `items` | 随身物品 | list | 每条一件物品 |
| `injured` | 受伤 | check | 布尔 |

这套模板覆盖全部 6 种字段类型，作为示例与起点。实际按故事改：悬疑故事要线索与嫌疑值，修仙故事要境界与灵气，日常故事要好感与行程。新建自己的模板、删掉用不到的字段，协议提示词随之改变。字段跟着模板走，仓库只带这一套通用模板，题材专用的模板由用户自建或导入。

### 2.4 导入导出与随卡存储

- 模板导出：单个模板 → `.json` 文件；导入反向。设置面板内嵌 JSON 文本框支持快速复制粘贴。
- 随卡存储：`writeExtensionField(characterId, 'freestatus', {templates, state})`，模板与当前状态写入角色卡扩展字段，随卡导出/导入（借鉴 ST-StatusTracking）。群聊时 `characterId` 可能为 undefined，此时跳过随卡、仅全局/每聊存储。

## 3. AI 输出协议（规范见 docs/protocol.md，此处摘要）

回复尾部一个 ` ```fs ` 代码块，内容为单个 JSON 对象，有值快照（只输出当前有值的 key，省略即清空）：

````
```fs
{"_char":"玲","affection":45,"mood":"平静","condition":"一切正常","impressions":{"老师":50},"items":["手机","钥匙"],"injured":false}
```
````

- `_` 前缀键为元数据（如 `_char` 归属角色，缺省=消息生成者），不渲染。
- 有值快照把「输出什么」交给模型判断：没值、不适用、剧情未涉及的字段省略，状态栏也就不渲染，字段多也不占行；输出 token 只花在有值的键上。
- delta 增量模式暂未实现（ScenePulse 的数据：比有值快照再省 token，代价是需要定期全量兑底，小模型容易写漏）。
- 协议提示词由设置面板「复制协议提示词」按当前模板自动生成，内容含字段清单、类型约束、one-shot 示例、当前状态回注位。

## 4. 解析与容错

| 情况 | 处理 |
|---|---|
| 找到多个 ` ```fs ` 块 | 取最后一个（与正文最新情节一致） |
| JSON 解析失败 / 括号不闭合（回复被截断） | 丢弃本次，沿用旧状态，静默不报错 |
| 键未输出（AI 判断无值或写漏） | 视为无值，该字段从状态栏隐藏；锁定字段保留旧值 |
| 未知键 | 通用类型推断渲染，进「其他」分组，可收编/忽略 |
| 值类型不符字段 kind | 按 kind 强制转换（number→string 取字符串；string→number 取数字，失败按 default） |
| 数值越界 | 钳到 [min, max] |
| 无 ` ```fs ` 块 | 状态不变（AI 忘输出时正常降级） |

解析入口只有一个函数：`parseStatusBlock(text) → {meta, values} | null`，所有事件路径共用。

## 5. 存储

| 数据 | 位置 | 保存时机 |
|---|---|---|
| 全局模板库 `templates[]`、设置 | `extensionSettings.freestatus` + `saveSettingsDebounced()` | 模板编辑/设置变更 |
| 每聊状态 `chars{角色→values/locks}`、当前模板 id、卡片折叠状态 | `chatMetadata.freestatus` + `saveMetadata()` | 状态更新/手改/切换模板 |
| 随卡镜像（模板+状态） | `writeExtensionField` | 用户点「写入角色卡」时 |

注意：`chatMetadata` 切换聊天后引用会变，一律在事件回调里重新 `getContext().chatMetadata` 取，不长期持有。

## 6. 事件挂钩

| 事件 | 动作 |
|---|---|
| `MESSAGE_RECEIVED` | 解析 ` ```fs ` → 合并状态 → 存储 |
| `CHARACTER_MESSAGE_RENDERED` | 隐藏消息内的原始 ` ```fs ` 块 → 刷新侧栏卡片 |
| `MESSAGE_SWIPED` / `MESSAGE_EDITED` | 从该 swipe 的消息重解析（有块则更新为该 swipe 状态；无块保持现状） |
| `CHAT_CHANGED` | 重载 `chatMetadata`，重渲染侧栏 |
| `GENERATION_ENDED` | 兜底刷新一次侧栏（防事件遗漏） |
| `APP_READY` | 挂载侧栏容器与设置面板 |

## 7. 回注双轨（用户自选，可全关）

回注让 AI 知道当前数值，防漂移，保持剧情与状态一致。每轮成本是状态串本身（约 20–40 token）。

| 轨道 | 机制 | 适用 |
|---|---|---|
| A. 自动注入（默认开，可关） | manifest `generate_interceptor` 在生成前注入：协议规则（「自动注入协议规则」开关，默认开，AI 由此知道输出格式，零配置可用）+ 当前状态紧凑串（状态暂无时提示 AI 按剧情初始化） | 零配置，不想管世界书的用户 |
| B. 宏（可选） | `macros.register('fs_state', …)` 注册 `{{fs_state}}`，展开为当前状态紧凑文本；用户在世界书/预设里自己控制位置 | 想精确控制注入位置、或想只对某模板字段注入 |

- 紧凑状态串格式（与协议同源）：`当前状态：好感=45，信任=30，心情=平静，状态=一切正常，印象={老师:50}，随身物品=[手机,钥匙]，受伤=否`（只含 `inject: true` 的字段）。
- 两轨可同时开（不推荐，会重复注入），设置面板给互斥提示。
- 回注关闭时插件只做显示；提示词里的「当前状态」行留空即可。

## 8. UI：侧边面板卡片

### 8.1 面板

- 常驻侧边面板（右侧），扩展工具栏图标切换显示/隐藏；宽度可拖，移动端折叠为浮动按钮点开抽屉。
- 暗色为主色调（酒馆常见深色主题），CSS 变量支持主题微调。

### 8.2 角色名卡片（核心交互）

```
┌────────────────────────────┐
│ ▸ 玲        😶平静  好感 45 │  ← 卡头：角色名 + 摘要（mood chip + 1-2 个关键值迷你条）
├────────────────────────────┤
│   （点击卡头展开/折叠）      │
│  好感   █████░░░░░  45      │  ← bar：进度条，点值即改
│  信任   ███░░░░░░░  30      │
│  心情   [平静]               │  ← chip
│  状态   一切正常…            │  ← text
│  印象   老师 ▓▓▓░░░░ 50     │  ← tag：键 + 迷你条
│  随身物品 [手机][钥匙]       │  ← list：标签组
│  受伤   [✗]                 │  ← check
└────────────────────────────┘
```

- 卡头：角色名（群聊时每角色一张卡，单聊一张），右侧摘要显示第一个有值的 mood chip 与第一个有值 bar 的迷你值；点击卡头展开/折叠，折叠状态（per chat per char）存入 `chatMetadata`。
- 展开区：按模板 `fields` 顺序渲染有值字段，无值字段默认隐藏；卡片底部「显示空字段 (N)」开关可临时展开空字段手动赋值（`showEmptyFields` 设置，默认关）。未知键汇入底部「其他」分组（带收编/忽略按钮）。
- 点值即改：点击 bar 数值进入输入态（也可直接拖动进度条），Enter/失焦提交，写回状态并保存；chip/text/tag/list/check 同理点击进入编辑（chip 输入短语、tag 增删键值行、list 增删标签、check 点击翻转）。手动改过的字段自动锁定，避免被下一轮快照清掉。
- 字段锁定：每项悬停出现 🔒 图标，锁定后 AI 更新被忽略（手改不受影响），锁图标常亮提示。
- 卡头工具：手动「重新解析此消息」（纠错兜底）、「写入角色卡」（随卡存储）。

### 8.3 移动端

面板转为底部抽屉/浮动按钮；卡片宽度自适应；触控下点值即改走点击而非 hover。

## 9. 设置面板

分组（Handlebars 模板 `settings.html`）：

1. 通用：启用开关、侧栏常驻开关、暗色/主题色、面板宽度。
2. 模板：当前模板选择、字段表格（增删改、拖动排序、kind 选择器、上限/颜色/默认值/inject/locked 默认）、新建/复制/删除模板、导入导出 JSON、「写入角色卡」。
3. 协议：一键「复制协议提示词」、隐藏正则开关（自动注册 ` ```fs ` 隐藏正则）、one-shot 示例编辑。
4. 回注：轨道选择（关 / interceptor / 宏）、注入字段范围预览（只含 `inject:true`）、注入文本格式预览。
5. 诊断：最近一次解析结果预览、解析失败计数、清空本聊状态。

## 10. 数值一致性与防漂移

- 提示词硬规则：变化必须有正文情节依据，正文没写的沿用当前值（回注提供当前值锚点）。
- 钳制：快照语义下模型直接给终值，单次变动不做硬限，但值域钳 [min,max]；`bar` 的 default 用于「显示空字段」时的占位显示。
- 手改优先：手动改过的字段自动锁定，以手改为准且不受 AI 快照影响；解锁后恢复 AI 控制。
- 解析失败不推进版本号，AI 下一轮看到的仍是旧状态，自然重试。

## 11. 不做

- 独立 LLM 抽取不做，保持零额外请求的轻量定位。
- 渲染位置就是侧栏卡片，消息内嵌卡片/底部 HUD/图表历史不实现。
- 一个聊天一套模板够用，多 tracker 并行（zTracker Modules 那种）不实现。
- 独立扩展，可与任何扩展共存（隐藏正则避免与状态栏类扩展冲突即可），不依赖酒馆助手。
